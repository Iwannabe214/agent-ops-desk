# AgentOps Desk｜智能体平台运营后台模拟系统

一个面向“智能体平台运营专员”岗位制作的个人模拟项目。项目不训练模型、不复制企业后台，而是把岗位中的日常运营工作做成一个可以实际操作的网页系统。

> 重要声明：仓库内的姓名、部门、账号、调用量和问题记录均为虚构演示数据。项目应在简历中标注为“个人模拟项目”，不得描述为真实企业运营经历。

## 在线功能

- 账号开通：登记申请，核验用途、角色、资源范围和有效期，填写审批意见后开通或驳回；
- 应用审核：提交时保留测试用例、失败样本、数据来源、异常兜底、隐私和使用指引证据；待审核应用按7项维度及分档标准完成100分审核；命中安全风险时执行一票否决，整改重提时升级版本并保留历史；
- 问题闭环：新问题先进入待响应，填写响应渠道、用户回复、初步判断、协作人和下次反馈后动态计算SLA；状态必须按允许的复现、处理、验证和关闭路径推进；
- 跨部门跟进：记录协作部门/人员、阻塞点、承诺日期、下一步动作及每次沟通结果，形成可追溯时间线；
- 数据看板：汇总待办、风险、调用趋势和问题分布；
- 两个月数据：默认生成60天日指标，并提供适量账号、应用和问题工单；
- CSV 导出：导出问题台账和运营指标，可在 Excel 中复核；
- Excel分析包：网站可直接下载包含6张工作表、公式KPI、条件格式和3个图表的运营工作簿；
- 应用健康度：按统计区间展示调用量，并结合成功率、负反馈率、知识库未命中率、人工介入和发布状态生成运营动作建议；
- 运营周报：根据当前台账生成 Markdown 周报初稿，完成统计范围、来源、异常、口径、AI结论及脱敏6项人工核验后才可下载；
- 使用与推广材料：站内提供新手术语、SLA、3分钟演示路径和JD映射，并可下载Markdown平台介绍；社交分享预览图可用于GitHub项目展示；
- FAQ 管理：已关闭问题可一键生成FAQ初稿，人工核验后保存并关联来源工单；
- 操作日志：记录关键状态变化，保证流程可追溯；
- 本地持久化：页面操作保存在浏览器 `localStorage` 中。

## 如何运行

本项目没有第三方依赖，不需要安装 Node.js 或数据库。

### 方法一：直接打开

双击 `index.html`。

### 方法二：本地HTTP服务

在项目目录运行：

```bash
python -m http.server 8000
```

浏览器访问 `http://localhost:8000`。

## 3分钟演示脚本

按以下顺序向面试官演示：

1. **使用指南**：先讲清Agent、Skill、知识库、SLA、优先级和项目边界；
2. **运营总览**：说明待审核账号、应用、未闭环问题和重点风险；
3. **账号开通**：打开一条申请，检查系统按角色给出的最小权限建议和有效期；可直接确认开通，也可切换为驳回并查看审批意见和到期日联动；
4. **应用审核**：选择“未评分”的待审核应用，先展示测试和风险证据，再按可解释的分档标准完成评分；
5. **问题闭环**：先对待响应工单填写一次完整首次响应，再打开处理详情，说明状态为什么不能跳过验证直接关闭；追加一条跨部门跟进记录；
6. **FAQ与周报**：把已验证关闭的问题沉淀为FAQ；切换7/30/60天口径，完成6项人工核验后下载简报。

演示时要强调：Agent只是平台中的运营对象，核心工作是资源审核、用户支持、问题闭环和数据复盘。

## 如何把项目变成自己的作品

1. 点击“重置演示数据”，从初始状态开始；
2. 自己新增2个账号申请、2个应用和5个问题；
3. 为每个问题解释分类和优先级依据；
4. 完成至少1个问题从登记到关闭的完整流程；
5. 下载Excel分析包，亲自核对4个KPI公式、问题台账筛选和3个图表；
6. 检查自动生成的周报，手动修改不准确或缺少依据的结论；
7. 保存以下截图：运营总览、应用审核、问题台账、数据周报；
8. 将项目部署到GitHub Pages，并把链接放进简历。

不要只展示仓库里的默认数据。面试前必须亲自完成一次完整操作，并能解释每一个字段和规则。

## GitHub Pages部署

最适合新手的方式是将发布包内容上传到公开仓库根目录，再到 `Settings → Pages` 选择 `Deploy from a branch`、`main` 和 `/(root)`。完整截图路径、更新方式及404排查见 [DEPLOY_GITHUB_PAGES.md](DEPLOY_GITHUB_PAGES.md)。

发布后，其他电脑可以通过公开网址打开网站；但是新增、审批和关闭等操作只保存在每台电脑自己的浏览器中，不会跨设备同步。这是静态作品集的正常限制，不影响面试演示。

## 简历写法

项目名称建议：

> **智能体平台运营后台模拟系统｜个人项目**

可以使用以下描述，但只保留自己真正理解并完成的部分：

- 围绕智能体平台运营场景，借助AI工具设计并实现账号开通、Agent/Skill审核上下架、用户问题闭环、FAQ及数据周报等7个运营模块。
- 构造近60天适量模拟运营数据，覆盖账号申请、应用审核、日调用量、活跃用户和问题工单，并支持重新生成及CSV导出核验。
- 建立Agent/Skill发布前审核评分卡，从场景、功能、异常、输出、知识库、安全和运营准备7个维度评分，并设置隐私越权、危险操作等一票否决规则。
- 建立七类问题与P0-P3优先级体系，按优先级设置首次响应SLA，设计“待确认—已复现—处理中—待验证—已关闭”的闭环流程，记录复现、初因、处理、验证及用户反馈。
- 设计跨部门协作跟进台账，记录协作对象、阻塞点、承诺日期、下一步动作和逐次沟通结果，支持对逾期承诺进行运营待办提醒。
- 实现7/30/60天统计口径切换，建立应用运营健康度判断，结合调用量、成功率、负反馈率、知识库未命中率和人工介入次数输出整改、审核或持续监控动作。
- 制作包含6张工作表、公式KPI、条件格式及趋势/分布图表的Excel分析包，并提供当前问题、协作、应用及指标CSV导出用于核验。

不应写成：

- 负责某企业智能体平台运营；
- 服务真实用户XX人；
- 提升真实平台效率XX%；
- 独立开发企业级AI平台。

## 隐私与安全

- 不要把真实用户姓名、手机号、账号、聊天记录或简历内容提交到公开仓库；
- 不要将API Key、平台密钥或内部链接写入代码；

- AI生成的统计与周报结论必须人工核验。
