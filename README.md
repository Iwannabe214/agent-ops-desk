# AgentOps Desk｜智能体平台运营后台

AgentOps Desk 是一个智能体平台运营流程演示系统，覆盖账号权限、Agent / Skill 审核、用户问题闭环、跨部门跟进、FAQ 管理和数据周报。

> 数据声明：仓库中的姓名、部门、账号、调用量和问题记录均为虚构演示数据，不包含真实企业或用户信息。

## 在线功能

- **账号权限**：核验申请用途、角色、资源范围、权限期限和审批意见；
- **应用治理**：提交 Agent / Skill 的测试证据、知识来源、异常兜底和隐私说明，通过评分卡完成审核、整改、上架与下架；
- **问题闭环**：记录问题分类、P0—P3 优先级、首次响应、复现、定位、处理、验证和用户反馈；
- **跨部门跟进**：记录协作人、阻塞点、承诺日期、下一步动作和逐次沟通结果；
- **FAQ 管理**：将完成验证和用户反馈的已关闭问题沉淀为标准回答；
- **数据周报**：统计 7 / 30 / 60 天调用量、活跃用户、问题分布、闭环率和首次响应 SLA；
- **人工核验**：周报下载前检查统计范围、数据来源、异常值、指标口径、AI 结论和隐私脱敏；
- **数据导出**：支持问题、协作、应用和日指标 CSV，以及初始数据 Excel 分析包；
- **操作日志**：记录审批、审核、状态变化和报告核验等关键动作。

## 主要业务流程

### 账号开通

```text
提交申请 → 核验用途 → 确认角色与资源范围 → 设置有效期 → 开通或驳回 → 保存审计记录
```

### 应用审核

```text
提交应用与测试证据 → 七维评分 → 风险检查 → 通过 / 整改 / 驳回 → 上架或下架
```

审核评分共 100 分，包含场景完整性、功能可用性、异常处理、输出质量、知识库质量、安全与隐私、运营准备。隐私越权、关键数据持续编造、危险操作缺少人工确认或没有异常兜底属于一票否决项。

### 问题闭环

```text
用户反馈 → 分类和定级 → 首次响应 → 复现 → 初步定位 → 协作处理 → 回归验证 → 用户反馈 → 关闭 → FAQ沉淀
```

问题状态按照“待确认 → 已复现 → 处理中 → 待验证 → 已关闭”推进，不能跳过验证直接关闭。

## 优先级与首次响应 SLA

| 优先级 | 首次响应时限 | 典型情况 |
|---|---:|---|
| P0 | 15分钟 | 大面积不可用、严重安全或数据风险 |
| P1 | 2小时 | 多名用户或关键流程受到明显影响 |
| P2 | 24小时 | 局部问题，存在替代方案 |
| P3 | 48小时 | 一般咨询、体验优化或需求建议 |

首次响应不等于问题已经解决。系统会记录响应渠道、回复内容、初步判断、协作人和下一次反馈时间，并与 SLA 截止时间比较。

## 如何运行

项目为纯静态网页，不需要数据库或第三方依赖。

### 直接打开

双击 `index.html`。

### 本地 HTTP 服务

在项目目录运行：

```bash
python -m http.server 8000
```

浏览器访问 `http://localhost:8000`。

## GitHub Pages 部署

将发布目录中的文件上传到公开仓库根目录，然后在 `Settings → Pages` 中选择 `Deploy from a branch`、`main` 和 `/(root)`。

完整说明见 [DEPLOY_GITHUB_PAGES.md](DEPLOY_GITHUB_PAGES.md)。

## 数据说明

- 默认包含近 60 天的模拟指标及适量账号、应用和问题记录；
- CSV 和 Markdown 简报使用当前浏览器中的最新操作数据；
- Excel 分析包展示初始数据的公式、条件格式、指标口径和图表；
- 页面操作保存在当前浏览器的 `localStorage` 中，不同电脑之间不会同步；
- 清理浏览器网站数据后，页面会恢复为默认演示数据；
- AI 生成的分类、FAQ 或周报内容需要人工核验。

## 隐私与安全

- 不要向公开仓库提交真实姓名、手机号、聊天记录、内部链接或账号信息；
- 不要在代码中保存 API Key、密码、Cookie 或平台密钥；
- 使用外部资料时应先脱敏，并遵守原始资料的保密要求；
- AI 生成的统计与运营结论必须回到明细数据进行核验。
